01 · Overview
What Fixture AI actually does
The big picture before we get into the maths

Fixture AI is a statistical football prediction engine. It takes publicly available match and standings data, runs it through a series of mathematical models, and outputs probabilities for three types of outcomes per fixture: the result (home win / draw / away win), the goals total (over or under 2.5), and whether both teams will score.

The predictions are not guesses or opinions. Every number you see — the 63% home win probability, the 58% BTTS likelihood — is the result of a deterministic calculation. Given the same input data, the model will always produce the same output. There is no randomness and no black-box machine learning.

Why no machine learning?
Training a reliable ML model for football requires millions of historical rows of labelled data and months of compute. The free football API tier provides current-season data only. Instead, Fixture AI uses well-established statistical methods — Poisson distributions and strength-of-schedule scoring — that are mathematically sound without requiring training data. These are the same methods used as baselines by professional quant sports analysts.

The system works in two stages. First it scores each team using their season standings — position, win rate, goals scored and conceded. Then it converts those scores into probabilities using the Poisson model for goals and a custom draw-adjusted model for the result market.

02 · Data
Where the data comes from
Every API call made, what it returns, and how it is used

All data comes from the football-data.org API (free tier). Each league requires 3–4 API calls to fully load. The free tier is rate-limited to 10 requests per minute, so the app throttles itself to 9 per minute and loads leagues sequentially — one at a time — to avoid hitting the ceiling.

API CallEndpointWhat we use it for
1 · Competition info /competitions/{league} Get currentMatchday (to auto-detect which gameweek is active) and numberOfMatchdays (to know the maximum GW for navigation). Different leagues have different totals — Bundesliga has 34, Championship has 46, Premier League has 38.
2 · GW status check /competitions/{league}/matches?matchday=N Check whether the current matchday's matches are all FINISHED. If they are, we advance to the next gameweek (e.g. if GW5 is over, we show GW6). If some are still SCHEDULED, we stay on the current GW. This is skipped for past seasons.
3 · Standings /competitions/{league}/standings The full league table. For every team: position, points, played, won, drawn, lost, goals for (GF), goals against (GA). This is the backbone of all predictions — the model uses GF/played and GA/played as proxies for attacking and defensive strength.
4 · Fixtures /competitions/{league}/matches?matchday=N The actual matches for the selected gameweek — home team, away team, kickoff time, and score (if finished). This populates the fixture cards.
Session caching
Once a league is loaded, its predictions are saved to sessionStorage. Navigating away (to the bet slip, for example) and coming back skips all API calls for that league — the data is restored instantly from cache. The cache is cleared when you change season or manually switch to a new league for the first time.

One deliberate design decision: we do not make per-team API calls. Earlier versions fetched each team's recent match history (10 games × ~18 teams = ~180 extra calls per league). This was removed to make the app practical on the free API tier. The trade-off is that "form" is inferred from season statistics rather than match-by-match results. The model is more stable but slightly less reactive to short-term slumps or streaks.

03 · Team Scoring
The strength algorithm
How we turn league standings into a single comparable score for each team

Every team in a fixture gets a strength score between 2 and 98. This score is what drives the result market probabilities. A score of 75 means the team is significantly above average; a score of 35 means they are below average. The score is never 0 or 100 — the model never considers any outcome impossible.

The score is built from three components, blended together:

1
Position component (60% weight)
The team's current league rank is converted to a 0–80 scale. The league leader scores 80, the bottom team scores 30, and everyone scales linearly between those bounds.

posScore = 30 + ((totalTeams − rank) / totalTeams) × 50

This captures structural quality — a team sitting top of the table has been consistent across the whole season. We weight it at 60% because position is the most robust signal we have from a single standings API call.
2
Win rate component (30% weight)
The fraction of games won so far (won / played), scaled to 0–100. A team that has won every game gets 100; a team with no wins gets 0. This adds granularity that position alone misses — two teams on the same points can have very different win rates depending on how many draws they have accumulated.

winScore = (won / played) × 100
3
Draw rate component (10% weight)
Draws are a meaningful signal. A team with many draws is harder to beat than one that either wins or loses decisively. We add 10% weight to the draw rate so that solid-but-inconsistent teams aren't undervalued.

drawScore = (drawn / played) × 100
Team strength score formula
── Input ─────────────────────────────────────────────────────── rank = team's current league position (1 = leader) totalTeams = total clubs in the league (e.g. 20 for PL) played = matches played this season won, drawn = results so far ── Components ────────────────────────────────────────────────── posScore = 30 + ((totalTeams − rank) / totalTeams) × 50 ← 30–80 range winScore = (won / played) × 100 ← 0–100 range drawScore = (drawn / played) × 100 ← 0–100 range ── Blend ──────────────────────────────────────────────────────── rawScore = posScore × 0.60 + winScore × 0.30 + drawScore × 0.10 ── Clamp ──────────────────────────────────────────────────────── teamScore = max(2, min(98, rawScore)) ← never 0 or 100
Early season accuracy
When fewer than 5 games have been played, all three components are noisy. A team that won their first two games by luck can outscore a genuinely stronger team. Treat predictions in the first 4–6 gameweeks of any season as indicative only. The model becomes more reliable around GW8–10 when standings begin to reflect true quality.

The attack and defence values used for goal markets are derived separately from the same standings data. attack = GF / played gives the average goals scored per game, and defense = GA / played gives the average conceded. These are not used in the strength score — they feed directly into the Poisson model described in section 05.

04 · Result Market
Home / Draw / Away probabilities
How two team scores become three percentages that add up to exactly 100%

Once each team has a strength score, we need to convert those two numbers into three probabilities: P(Home Win), P(Draw), P(Away Win). This is done in three steps: apply home advantage, compute draw probability, then split the remainder between home and away.

1
Home advantage adjustment
Playing at home is a well-documented statistical advantage in football. Across all major European leagues, home teams win roughly 45–48% of matches compared to ~27% for away teams. We model this by adding +8 points to the home team's score before any probability calculation.

This is a flat adjustment — it doesn't vary by league or team. In reality, some venues (Anfield, Signal Iduna Park) have a larger crowd effect than others, but we don't have venue-specific data on the free API tier.

homeAdj = teamScore(home) + 8
awayAdj = teamScore(away)
2
Draw probability
Draws are the hardest outcome to model. They are most likely when two teams are closely matched, and least likely when there is a large gap in quality. We use a formula that starts at 32% base draw rate (the empirical average in professional football) and reduces it as the gap between the two teams' adjusted scores grows:

gap = |homeAdj − awayAdj|
P(Draw) = max(14%, min(34%, 0.32 − gap × 0.006))

So two teams with equal scores get a 32% draw probability. If one team is 30 points stronger, the draw drops to 14%. The floor of 14% ensures draws remain possible even in mismatches; the ceiling of 34% prevents draws dominating in even contests.
3
Split home/away and normalise
With the draw probability fixed, the remaining probability (1 − P(Draw)) is split between home and away proportionally to their adjusted scores. Both values are then normalised so all three probabilities sum to exactly 100%.

P(Home) ∝ homeAdj × (1 − P(Draw))
P(Away) ∝ awayAdj × (1 − P(Draw))
P(Home) + P(Draw) + P(Away) = 100% (always)
Complete result market formula
homeAdj = teamScore(home) + 8 awayAdj = teamScore(away) gap = |homeAdj − awayAdj| P(draw) = clamp(0.32 − gap × 0.006, 0.14, 0.34) scale = 1 − P(draw) rawHome = (homeAdj / (homeAdj + awayAdj)) × scale rawAway = (awayAdj / (homeAdj + awayAdj)) × scale ── Normalise to exactly 100% ──────────────────────────────────── total = rawHome + rawAway + P(draw) P(home) = round(rawHome / total × 100) P(away) = round(rawAway / total × 100) P(draw) = 100 − P(home) − P(away) ← absorbs rounding errors

05 · Goal Markets
Over/Under 2.5 & Both Teams to Score
How the Poisson distribution turns goal averages into goal market probabilities

Goal markets require a different model from the result market. Instead of comparing two scores against each other, we need to estimate the number of goals each team is likely to score in a specific match. We use the Poisson distribution — the standard statistical tool for modelling discrete event counts where individual events are independent (each goal is independent of the previous one).

What is the Poisson distribution?
The Poisson distribution models "how many times does something happen in a fixed period, given we know the average rate?" If a team scores an average of 1.8 goals per game, the Poisson model tells us: P(0 goals) = 16.5%, P(1 goal) = 29.7%, P(2 goals) = 26.7%, P(3 goals) = 16.0%, and so on. Football goals are not perfectly Poisson (teams play more defensively when ahead), but the model fits observed match goal distributions well enough to be industry-standard.
1
Compute league average goals per game
We need a baseline to compare each team against. Since we only have the two fixture teams' data per call, we use their combined average as a proxy for the league average:

leagueAvgScored = (homeGF/played + awayGF/played) / 2
leagueAvgConceded = (homeGA/played + awayGA/played) / 2

This is an approximation — a full league average would be more accurate but requires fetching all teams' data. The approximation is reasonable in most match-ups.
2
Compute attack and defence strengths
Each team's attack and defence are rated relative to the league average. A team that scores 2.4 goals per game when the league average is 1.6 has an attack strength of 1.5 (50% above average). A team that concedes 2.0 per game against a league average of 1.4 has a defence strength of 1.43 (43% weaker than average).

homeAttackStr = (homeGF/played) / leagueAvgScored
homeDefenceStr = (homeGA/played) / leagueAvgConceded
(same for away team)
3
Compute expected goals (xG) per team
The expected goals for each team in this specific match combines their attack strength against the opposition's defensive weakness, scaled by the league average scoring rate. The home team also gets a 10% home scoring boost (empirically observed across European leagues).

xG(home) = homeAttackStr × awayDefenceStr × leagueAvgScored × 1.1
xG(away) = awayAttackStr × homeDefenceStr × leagueAvgScored

xG values are clamped to a realistic range of [0.2, 4.5] — no team is expected to score fewer than 0.2 or more than 4.5 in any single match.
4
Apply the Poisson formula
Given an expected goals value λ, the probability of exactly k goals is:

P(X = k) = (λᵏ × e⁻λ) / k!

We compute this for every combination of home and away goals to build a full match goals distribution. For Over 2.5, we sum the probabilities of all combinations where home + away goals ≤ 2, and subtract from 1. For BTTS, we check whether each team scores at least one goal independently.
Goal market formulae
── Poisson probability ────────────────────────────────────────── P(X = k) = (λᵏ × e⁻λ) / k! ← where λ = expected goals ── Over 2.5 goals ─────────────────────────────────────────────── P(total ≤ 2) = Σ P(home=h) × P(away=a) for all h+a ≤ 2 P(Over 2.5) = 1 − P(total ≤ 2) ── Both Teams to Score ────────────────────────────────────────── P(home ≥ 1) = 1 − P(home = 0) = 1 − e⁻λh P(away ≥ 1) = 1 − P(away = 0) = 1 − e⁻λa P(BTTS Yes) = P(home ≥ 1) × P(away ≥ 1) ← independent events ── Expected goals ─────────────────────────────────────────────── λ(home) = homeAttackStr × awayDefenceStr × leagueAvg × 1.1 λ(away) = awayAttackStr × homeDefenceStr × leagueAvg clamped to [0.2, 4.5]

Low sample warning
When either team has played fewer than 8 games, goal market predictions are flagged with a ⚠ low-sample warning on the card. The Poisson model needs a stable goals-per-game average to be meaningful. A team that scored 4 goals in their opening match will have an inflated attack strength that corrects itself over the following weeks. Always treat early-season goal markets with extra scepticism.
06 · Confidence
Stars, confidence scores, and how to read a fixture card
What the stars mean and how to interpret the numbers

Each fixture card displays a 1–5 star rating in the top left. This is a direct measure of how confident the model is in its predicted outcome. Specifically, it is the probability of the top predicted outcome:

StarsTop outcome probabilityWhat it means
★★★★★Over 80%Strong edge. The model sees a clear favourite. Consider with good odds.
★★★★65%–80%Solid edge. A meaningful lean towards one outcome.
★★★50%–65%Moderate lean. The favourite is likely but the match is competitive.
★★38%–50%Slight lean. All three outcomes remain in play.
★Below 38%Very open. Treat as a coin flip — avoid staking high on this.
How to use confidence ratings
High confidence ratings (4–5 stars) do not mean the outcome is guaranteed. A 75% confidence means the model expects the result to be wrong 1 in 4 times. What high confidence does mean is that the model has found a statistically meaningful edge, which is exactly what you want when building a bet slip. Focus on 4–5 star picks, verify the odds make sense (implied probability should be below the model's probability), and keep stakes proportional to confidence.

The card also shows three percentage pills: H / D / A for home, draw, and away win probability. These always sum to 100%. The highlighted pill (in the card's accent colour) is the predicted outcome. When a match is finished, the card glows green if the prediction was correct or red if it was wrong.

Below the percentage row you will see three badges: O/U (over/under 2.5 probability), BTTS (both teams to score), and xG (expected goals, e.g. "1.8–1.2" meaning home xG 1.8, away xG 1.2). These are colour-coded: green if the model favours that side of the market (≥55%), red if it disfavours it (≤45%), and grey if it's near 50/50.

07 · Bet Slip
How the bet slip works
Adding bets, changing picks, tracking results

The bet slip is a personal tracking tool. It does not connect to any bookmaker and does not place real bets. Its purpose is to let you log which predictions you are acting on, record your odds, and track your results over time.

➕
Adding a match
Tap the + button on any fixture card. The match is added with the AI's predicted pick pre-filled. The bet is stored in your browser's localStorage — it persists between sessions but is local to your device.
⚡
Changing your pick
On the bet slip, each bet shows a pick dropdown. Only AI-approved options appear (those with ≥50% predicted probability). You can switch from "Home Win" to "Over 2.5" if both are AI-favoured, but cannot select "Away Win" if the model gives it less than 50%.
📊
Recording odds
Tap the odds field on any bet card to enter the decimal odds from your bookmaker. This lets you track expected value — if the model says 65% and the bookmaker offers 2.00 (implying 50%), that is a positive-value bet.
✓
Setting results
Tap the status pill (⏳ PENDING) to open a dropdown with Won / Draw / Lost / Remove options. The card border changes colour to reflect the result: green for won, amber for draw, red for lost.

The sidebar (desktop) and drawer (mobile) show a live summary: total bets, and counts by status. The "Remove all" button in the sidebar removes all bet cards from the list but preserves the summary counts — useful for clearing a gameweek's worth of bets while keeping a record of your overall hit rate.

08 · Limitations
What the model does not know
An honest account of where the predictions can go wrong
🤕
Injuries and suspensions. The API does not provide squad availability data on the free tier. A team playing without its first-choice goalkeeper, striker, or holding midfielder will still be rated on its season statistics. A missing key player can shift a 65% prediction to closer to 50/50 in reality. Always cross-check injury news before committing to a stake.
📅
Early season noise. In the first 5–8 gameweeks, standings are unstable. One lucky goal or one defensive error can place a team in the wrong half of the table. The model has no way to distinguish a genuine top-half team who had a bad start from a bottom-half team who fluked an early win. Confidence ratings are technically correct but based on unreliable inputs.
💼
Manager changes. A newly appointed manager can fundamentally change a team's tactical shape, defensive solidity, and motivational level within days. The model sees the same statistics before and after the change. This is one of the most common reasons a high-confidence prediction goes wrong.
🏆
End-of-season motivation. A top-half team that has secured European qualification, or a bottom-half team that has already been relegated, may field a weakened squad or play without full intensity. The model has no awareness of these motivational dynamics and will overestimate the strength of teams "coasting" at the end of a season.
🌤
Weather, pitch, and cup congestion. A team playing their third match in seven days on a heavy pitch in December performs differently to the same team in peak condition in September. None of these contextual factors are available through the API.
⚽
Tactical mismatches. A low-scoring defensive team can neutralise a high-scoring attack through specific tactical setups, regardless of what the statistics say. The Poisson model assumes scoring rates are independent — it does not account for one team deliberately sitting deep and hitting on the counter.
🌍
Cup competitions and non-domestic leagues. The World Cup and Euro Championship have very different competitive dynamics to domestic leagues. Teams rest players; knockout-stage mentality differs from league-game mentality; group-stage incentives vary. The model applies the same algorithm regardless — treat international tournament predictions as lower confidence than domestic league predictions.
Gambling responsibly
Fixture AI is a statistical tool, not a tipster service. No model — however sophisticated — can predict football outcomes with certainty. Even the highest-confidence predictions are wrong a meaningful fraction of the time. Never bet more than you can afford to lose, and treat the predictions as one input among many rather than a definitive answer.
09 · Glossary
Terms explained
Plain-English definitions of every technical term used in the app
TermDefinition
xGExpected Goals. The number of goals a team is statistically expected to score in a match, based on their attack strength and the opposition's defensive weakness. Not to be confused with shot-based xG used by advanced analytics — ours is derived from season averages.
Poisson distributionA mathematical model for counting how many times a random event occurs in a fixed time period, given a known average rate. Used here to model goal counts per match.
Over 2.5A bet that the match will contain 3 or more total goals. "2.5" is not a possible score — it is a line set between 2 and 3 goals so there is no push (tie). Over 2.5 means 3+ goals; Under 2.5 means 0, 1, or 2 goals.
BTTSBoth Teams To Score. A market where you predict whether both the home and the away team will score at least one goal in the match. BTTS Yes means both teams score; BTTS No means at least one team keeps a clean sheet.
Team scoreFixture AI's internal 0–98 rating for a team, combining their league position (60%), win rate (30%), and draw rate (10%). Used as the primary input for result-market probabilities.
Home advantageThe statistically observed tendency for home teams to win more often than away teams at the same quality level. Modelled as a flat +8 point addition to the home team's score.
Draw probabilityCalculated as 32% base minus a penalty for the quality gap between teams. Larger mismatches produce fewer draws; closely matched teams produce more draws.
Attack strengthA team's average goals scored per game, divided by the league average. A value above 1.0 means the team scores more than average; below 1.0 means less than average.
Defence strengthA team's average goals conceded per game, divided by the league average. A value above 1.0 means the team concedes more than average (weaker defence); below 1.0 means tighter (stronger defence).
ConfidenceThe probability of the top predicted outcome. A confidence of 70% means the model's top pick is expected to occur 70 times out of 100. Displayed as a 1–5 star rating on each fixture card.
Gameweek (GW)A round of fixtures in a domestic league season. Each team typically plays once per gameweek. The app auto-detects the current active or upcoming gameweek and navigates to it by default.
Decimal oddsThe bookmaker's pricing format used in Europe and Australia. Decimal odds of 2.50 mean you receive 2.50× your stake back if you win (including your original stake), implying a 40% probability. Implied probability = 1 / decimal odds.
Positive expected value (+EV)A bet is +EV when the model's probability is higher than the bookmaker's implied probability. Example: model says 65%, bookmaker offers 2.00 (implying 50%) — this is +EV. Over the long run, consistently finding +EV bets should produce profit.
Low sample warningA ⚠ flag shown on goal market predictions when either team has played fewer than 8 games. With a small sample, the averages used by the Poisson model are unreliable and the predictions carry higher uncertainty than usual.
SessionStorageA browser feature that stores data for the duration of a browser tab session. Fixture AI uses it to cache prediction data so navigating between pages is instant. The cache clears when you close the tab or change the season.
